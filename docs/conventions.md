# Typeway conventions

This is the spec generators and the CLI are built against. It is
normative for generated apps. The playground at
`apps/playground-with-tanstack` sketches most of this and is allowed
to lag where catching up is not cheap; gaps are listed at the end.

Read this file first. Each section below is expanded in a sibling
page with compiling snippets for the current stack:

- Bun **1.4.4**
- Elysia **2.0.0-rc.4** (route config is the second argument, handler
  the third)
- Vite **8.3**
- TanStack Start **1.x** (`@tanstack/react-start` ^1.169)
- Drizzle ORM **1.0.0-rc.5** (`defineRelations`, no 0.x `relations()`)
- better-auth **1.7**
- TypeBox via Elysia's `t`
- Eden via `@elysia/eden` **2.0.0-rc.1** (`treaty`)

The product is conventions, docs, and generators. Integrations stay
thin and ejectable. Do not add a Typeway wrapper where Elysia,
Drizzle, or TanStack already have the primitive.

## Principles

1. **One place for every concern.** An agent that has seen one Typeway
   app can navigate every Typeway app. Folders and filenames are
   part of the API.
2. **One data path.** Domain data enters and leaves through typed
   Elysia routes. Pages call those routes through Eden. Models are
   not a second HTTP layer.
3. **Elysia's `t` is the only validator.** Request bodies, env, and
   model input share TypeBox schemas (`import { t } from "elysia"`,
   `import type { Static } from "typebox"`). Do not add Zod, Valibot,
   `@sinclair/typebox`, or a second TypeBox import. There is no
   `.static` on Elysia 2 schemas — use `Static<typeof schema>`.
4. **Registered Elysia routes win.** Anything unmatched is the
   frontend. Do not register a catch-all route; `@typeway/server`
   owns that.
5. **`src/server.ts` is the SSR entry, and the name is load-bearing.**
   Do not rename it.
6. **Docs travel with the code.** Generators are idempotent, accept
   `--dry-run --json`, always emit a passing test, and rewrite the
   managed `AGENTS.md` section.

## Canonical app tree

Generated by `typeway new`. Every path is load-bearing. See
[layout](./conventions/layout.md) for purpose and naming rules.

```
my-app/
├── AGENTS.md                     managed conventions for agents
├── README.md                     humans
├── llms.txt                      compact agent dump of this spec
├── package.json
├── tsconfig.json
├── bunfig.toml
├── drizzle.config.ts             schema: db/schema/index.ts, out: db/migrations
├── vite.config.ts
├── tsr.config.json
├── server.dev.ts                 typeway({ app, frontend: tanstack() }).dev()
├── server.prod.ts                typeway({ app, frontend: tanstack({ handler }) }).prod()
├── app/
│   ├── context.ts                ALS: getDb, getBackend, getRequest
│   ├── transaction.ts            nested calls join the outer tx
│   ├── errors.ts                 HTTPError.id catalog + typeBase
│   ├── models/                   singular module, queries only
│   ├── schemas/                  TypeBox input/output, shared with routes
│   ├── jobs/                     reserved (not generated yet)
│   └── mailers/                  reserved (not generated yet)
├── config/
│   ├── env.ts                    TypeBox-parsed process.env
│   ├── database.ts               drizzle({ client, relations })
│   ├── application.ts            merged per-env config
│   └── environments/
│       ├── development.ts
│       ├── test.ts
│       └── production.ts
├── db/
│   ├── schema/                   one table per file + relations.ts
│   ├── migrations/               drizzle-kit v1 folders
│   ├── seeds/
│   └── factories/
├── server/
│   ├── app.ts                    export backend + type Backend
│   ├── listen.ts                 Bun.serve + ALS fetch wrapper
│   ├── fetch-context.ts          buildAppContext / withFetchContext
│   ├── guards/auth.ts            session derive
│   └── routes/                   one resource per file + Eden spec
├── src/                          TanStack frontend
│   ├── server.ts                 LOAD-BEARING SSR entry
│   ├── router.tsx
│   ├── routeTree.gen.ts          generated, do not edit
│   ├── styles.css
```

Unit tests and request specs live **next to the source they cover**
(`app/models/article.test.ts`, `server/routes/articles.test.ts`).
`tests/` is for booting the real dev/prod server.

## The one data path

**Elysia routes are the only typed API. TanStack pages and loaders
call them through Eden. On the server that call is in-process
(`treaty(getBackend())`); in the browser it is HTTP
(`treaty(origin)`).** TanStack server functions are UI-local glue,
never domain CRUD.

In-process on the server, HTTP in the browser:

- Same Eden client type, no codegen.
- SSR loaders share the page request's AsyncLocalStorage (db handle,
  transaction, cookies) because `treaty(instance)` calls
  `app.handle(Request)` without a network hop.
- HTTP-to-self from SSR is a new request: new ALS, cookie-copy bugs,
  `PORT` coupling, and a second contract agents get wrong.
- The host Elysia instance and Vite's SSR module graph are **two
  module graphs**. ALS must be a `globalThis` singleton or SSR
  `getDb()` is a different store. The playground's file-backed
  SQLite workaround exists because its ALS is not yet process-global.

See [data path](./conventions/data-path.md) for the decision table,
the `api()` helper, and what server functions are still for.

## Models

- Tables: `db/schema/<plural>.ts`. Re-export from `db/schema/index.ts`.
- Relations: one `db/schema/relations.ts` using Drizzle v1
  `defineRelations`. Pass `{ relations }` into `drizzle()`.
- Queries: `app/models/<singular>.ts` exporting a const object
  (`Article`). Never import the table from a route or a page.
- `getDb()` is the only connection. Nested `transaction()` joins
  the outer tx. bun-sqlite transactions are **sync**.
- Input validation lives in `app/schemas/<singular>.ts` (TypeBox).
  Routes use that schema as `body` / `params` / `response`. Models
  may `Value.Check` for non-HTTP callers (jobs, console).

See [models](./conventions/models.md).

## Routes

- JSON lives under `/api`. Pages live at the unprefixed path
  (`/articles` is HTML, `/api/articles` is JSON).
- One file per resource: `server/routes/articles.ts`. Five actions:
  `index`, `create`, `show`, `update`, `destroy`.
- Export `backend` from `server/app.ts` and `export type Backend =
  typeof backend`. Method-chain every `.use()` so Eden sees the
  routes.
- Errors are Elysia `HTTPError.id("article.not_found", 404)` with
  `HTTPError.typeBase` set. **Return** them from handlers so Eden
  types the status union. Do not invent a parallel error envelope.
- better-auth is mounted as **named** `/api/auth` and `/api/auth/*`
  routes, never `.mount(auth.handler)` (that catch-all loses to the
  connect wildcard).

See [routes](./conventions/routes.md) and the [error catalog](./errors.md).

## Config / env

`config/env.ts` parses `process.env` with TypeBox at import time and
throws `typeway.env.invalid` on failure. `config/environments/*.ts`
holds non-secret per-env values. `config/application.ts` merges them.
`config/database.ts` opens Bun SQLite (or later Postgres), runs
migrations, and seeds in development.

See [config](./conventions/config.md).

## Testing

| Kind | Where | How |
| --- | --- | --- |
| Unit | next to source | `bun:test`, `getDb()`, factories |
| Request spec | `server/routes/<resource>.test.ts` | in-process `treaty(backend)` |
| Integration | `tests/` | real `server.dev.ts` / `dist/app` |

Request specs do not boot HTTP. Factories insert through `getDb()`.
Isolation: in-process tests may use `:memory:`; anything that
crosses the Vite SSR graph must use a file (two connections cannot
share `:memory:`).

See [testing](./conventions/testing.md).

## Agent-first

- `AGENTS.md` has a managed block between
  `<!-- typeway:conventions:start -->` and
  `<!-- typeway:conventions:end -->`. Generators rewrite it.
  Humans edit around it, not inside it.
- Package docs stay in `packages/*/README.md`. App knowledge stays
  in the app's `AGENTS.md` and `llms.txt`.
- `typeway routes --json` and `typeway models --json` are the
  introspection API. Agents must not scrape source to discover
  routes once the CLI exists.
- Generators: idempotent, `--dry-run --json`, always a passing
  test, never a second validation library.

See [agents](./conventions/agents.md).

## Generator order

Implement in this order. Later generators consume earlier JSON
contracts. The execution plan is
[plans/05-cli-and-generators.md](../plans/05-cli-and-generators.md).

1. **`packages/cli`** — **done (slice 1).** `typeway` bin: `new`, `dev`,
   `build`, `start`, `routes --json`. No generate yet. See
   [docs/cli.md](./cli.md).
2. **`typeway models --json`** — scan `app/models/` + `db/schema/`.
   Needed before generate so idempotence can see the world.
3. **`typeway generate model <name>`** — table, relations stub,
   TypeBox schema, model module, factory, unit test, AGENTS.md
   rewrite. Stops before HTTP.
4. **`typeway generate resource <name>`** — everything `generate
   model` does, plus the Elysia resource, Eden request spec,
   `backend` wiring, TanStack index + `$id` pages that call
   `api()`, and a loader test. This is the first generator that
   enforces the one data path.

Do not start `generate job`, `generate mailer`, or `add auth` until
resource round-trips through Eden in the playground.

## Playground gaps

Cheap alignments shipped with this spec are listed in the PR. The
playground is still allowed to differ in these ways:

| Playground today | Spec |
| --- | --- |
| `db/schema.ts` (single file) + `drizzle/` at app root | `db/schema/<table>.ts` + `db/migrations/` |
| `config/env.ts` is a hand-built object | TypeBox parse at boot |
| Notes page loads via TanStack server fn that calls `Note.*` | Loader calls Eden `api().api.notes.get()` |
| `src/data/`, `src/mutations/` | Do not generate these for domain data |
| No `app/errors.ts` / `HTTPError.typeBase` | Elysia `HTTPError.id` catalog |
| ALS is on `globalThis`, but `backend` is not in context yet | `getBackend()` from ALS for in-process Eden |

Do not "fix" the notes page onto Eden in this docs PR. That is the
first `generate resource` dogfood.

## Open questions

These are unresolved on purpose. Do not invent an answer in a
generator until the spec is updated.

1. **Eden treaty path for a prefixed `backend`.** **Locked.**
   `packages/cli/src/eden-path.test.ts` constructs `new Elysia({ prefix:
   "/api" }).get("/hello", …)`, treaties it, and calls
   `api.api.hello.get()`. Generators must emit that chain
   (`api.api.<plural>.get()`), not `api.<plural>.get()`. Snippets in
   this spec already match. A `treaty(\`${origin}/api\`)` client would
   drop the extra `.api` — do not generate that.
2. **`@elysia/eden` version.** Pinned conceptually at `2.0.0-rc.1`
   (`@elysia/eden@rc`). Elysia itself is `2.0.0-rc.4`. Confirm types
   line up before `packages/cli` depends on it. Never install
   `@elysiajs/eden` (the 1.x package).
3. **Postgres.** Examples are bun-sqlite (sync `.get()`, sync
   `transaction()`). Postgres is async. A later `typeway new
   --database postgres` variant must not pretend sqlite is async
   (Drizzle rejects `Promise` in bun-sqlite transactions).
4. **Primary keys.** Sqlite generated tables use integer
   autoincrement. Postgres will use text UUID. No default UUID on
   sqlite — it fights the playground and Better Auth's text ids
   are a separate generated schema.
5. **Nested transactions.** Today nested `transaction()` joins the
   outer tx (no savepoint). Savepoints are future work.
6. **`HTTPError.typeBase`.** Set to `https://typeway.dev/errors`.
   That host does not exist yet; `code` is the greppable identifier
   and this repo's [docs/errors.md](./errors.md) is the catalog.
7. **Jobs, mailers, realtime, caching.** Folders are reserved.
   File shape is not specified here.
8. **Irregular plurals.** Generators take `--name article` and
   default plural `name + "s"`. Pass `--plural people`. No
   inflection library.
9. **Better Auth CLI** still emits drizzle-orm 0.x `relations()`.
   Strip them after `auth generate` until upstream uses
   `defineRelations`. Playground documents this in
   `db/auth.schema.ts`.
10. **Isomorphic `api()` and the client bundle.** `src/lib/api.ts`
    must not pull `bun:sqlite` into the Vite client build. The
    generator's contract includes a test that the client chunk
    does not contain `bun:sqlite` or `drizzle`. If Vite still
    follows the server branch, fall back to two explicit imports
    (`api.ts` HTTP-only in loaders that also run on the client,
    `api.server.ts` only from `.server.ts` modules) and record
    that as a spec amendment.
11. **`typebox` as a direct app dependency.** Elysia 2 already
    depends on it. Generated apps should list `typebox` so
    `import type { Static } from "typebox"` is not a transitive
    ghost. Pin the same major Elysia uses (currently 1.x). The
    playground does not list it yet — keep TypeBox schemas as
    values (`NoteCreate`) without a `Static<>` alias until then.
