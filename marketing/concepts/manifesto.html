A manifesto, and then a waiting list

Everything you need. Nothing you'll have to undo.

Typeway is a batteries-included TypeScript framework in the spirit of Rails — assembled from libraries that already won, held together by conventions instead of wrappers.

Read the argument
01 / 05

We didn't write a runtime.

Bun runs it. Elysia serves it. Vite builds it. TypeBox proves it. Four projects that would each win on their own merit, and not one of them needs us to reinvent it.

What nobody has written is the part where they agree — one project layout, one validation story, one dev command, one way to deploy. That part is Typeway, and it is deliberately the thinnest thing that could work.

02 / 05

Conventions are the product.

Rails' real gift was never the code. It was that every Rails app looked the same, so every Rails developer was useful on their first morning. TypeScript never got that, and the cost is paid once per repository, forever.

Typeway ships conventions, docs and generators. The integrations underneath are small enough to read in an afternoon — that is the point, not an apology.

03 / 05

Everything stays ejectable.

A framework you cannot leave is a bet on the framework's authors being right forever. Typeway wraps as little as it can get away with: outgrow an integration and you drop down to the library underneath — a library you already know, because we picked the one you would have picked.

@typeway/connect has zero runtime dependencies. That number is a design constraint, not a coincidence.

04 / 05

Agents are reading this too.

A good share of the code landing in your repository next year will be written by something that has never read your README and never will. Conventions that are deterministic and greppable stopped being a matter of taste — they are the interface now.

So the docs ship as skills, AGENTS.md and llms.txt, and every generator installs the knowledge to use what it just wrote, right next to the code it wrote.

05 / 05

The hard part already runs.

Hosting a modern frontend inside a typed API server — one process, HMR, streaming SSR, neither side aware of the other — was the piece that could have failed. It didn't. It is built, dogfooded and measured against clean Elysia and standalone TanStack, back to back on one machine.

Every claim on this page is a measured ratio or a test that runs on every commit.

No launch numbers. No roadmap fiction.

Be there for v0.

One email when it is genuinely usable. No drip campaign, no countdown. Until then the work happens in the open, commit by commit.

We'll write once.
